# ghostref

**조용히 아무것도 가리키지 않는 참조**를 찾습니다. ([English](README.md))

```
npx ghostref .
```

의존성 0개.

---

## 무엇을 잡나

```js
document.querySelector('.card-titel').replaceChildren('Hi');
```

클래스 이름은 `card-title`입니다. 이 줄은 `null`을 돌려주고, 옵셔널 체이닝을
붙여 뒀으면 오류조차 안 납니다. 제목만 조용히 안 바뀝니다.

```css
.badge { border: 1px solid var(--lien); }
```

변수 이름은 `--line`입니다. CSS는 모르는 변수를 **아무 말 없이 버립니다.**
테두리가 그냥 안 생깁니다.

둘 다 지금 돌리고 계신 검사를 **전부 통과합니다.** 까닭은 구조적입니다 —
**이름과 정의가 다른 파일에 있고, 각 언어의 도구는 자기 파일만 읽습니다.**
ESLint는 스크립트를 보고 마크업을 못 봅니다. Stylelint는 스타일시트를 보고
스크립트를 못 봅니다. 그 **사이를 보는 사람이 없습니다.**

그래서 이것들은 사람이 화면을 보고 "뭔가 이상한데"라고 할 때만 발견됩니다.

## 규칙

| 규칙 | 잡는 것 | 기본 |
|---|---|---|
| `missing-selector` | `querySelector('.x')` 인데 `.x`를 아무도 안 만든다 | error |
| `missing-id` | `getElementById('x')` 인데 그 id가 없다 | error |
| `missing-css-var` | `var(--x)` 인데 `--x` 정의가 없다 | error |
| `unstyled-class` | DOM에 붙이는데 CSS 규칙이 없다 (효과 없음) | 꺼짐 |
| `dead-css-class` | CSS에 있는데 아무도 안 만든다 | 꺼짐 |
| `dead-css-var` | 정의했는데 아무도 안 읽는다 | 꺼짐 |

앞의 셋은 **조용한 고장**입니다 — `null`이 흘러가거나 선언이 버려지는데 그냥
넘어갑니다. 뒤의 셋은 죽은 코드라 빌드를 막을 거리가 아니어서, `--all`로
청할 때만 켜집니다.

## 런타임에 만드는 것을 압니다

클래스는 **어디서든** 생기면 됩니다. HTML에 없어도 됩니다.

```js
el.classList.add('is-open');                       // .is-open 생김
box.innerHTML = `<div class="cell">${v}</div>`;    // .cell 생김
const CLONE = 'item-clone';
el.classList.add(CLONE);                           // 상수도 풀어서 봅니다
<div className="card" />                           // JSX
el.style.setProperty('--gap', '4px');              // --gap 정의
```

**클래스 이름을 상수로 두는 꼴**을 반드시 풀어야 합니다. 라이브러리는 거의 다
그렇게 쓰고, 그걸 못 풀던 동안 Bootstrap 자기 테스트에서 수십 개의
**자신 있고 틀린** 발견이 나왔습니다.

## 판정하지 않은 것을 반드시 말합니다

```
not judged: 25 lookups built from variables
skipped missing-selector, missing-id — nothing given here declares markup
```

**조용히 건너뛴 것을 통과라 부르지 않습니다.** `querySelector('.' + name)`은
판정할 수 없으니 짐작하지 않고 세어서 보고합니다. 마크업이 하나도 없는
폴더를 주면 셀렉터 검사를 **아예 안 합니다** — 그 상황에서는 *모든* 조회가
깨진 것으로 보이고, 거짓 경보 한 장은 침묵보다 나쁩니다.

## 끄는 법

```js
document.querySelector('.서버가-붙이는것');  // ghostref-ignore
// ghostref-ignore-next-line missing-selector
/* ghostref-disable */                        // 이 파일 전체
```

**탈출구 없는 린터는 통째로 꺼집니다.** 그러면 진짜 발견까지 같이 사라집니다.

## 실제로 뭘 찾았나

한 번도 본 적 없는 14,000줄 앱에 0.14초 만에:

```
613  error  var(--바닥) is read but --바닥 is never defined
     did you mean var(--바탕) ?
642  error  var(--주의선) is read but --주의선 is never defined
     did you mean var(--주의점) ?
```

**진짜 버그 둘** — 판 하나의 배경색이 통째로 안 먹고, 알약 하나의 테두리가
안 그려지고 있었습니다. 둘 다 몇 주 묵은 것이고 둘 다 옆 이름의 오타입니다.
CSS 린터에는 안 보입니다(`var(--바닥)`은 문법상 완벽히 맞습니다). JS 린터에도
안 보입니다(JS가 끼어 있지 않습니다). 같은 코드의 셀렉터 조회 405개는
거짓 경보 **0개**로 지나갔습니다.

## 한계

이걸 분명히 적는 것이 요점입니다. 감추는 도구는 **믿을 눈금을 못 세웁니다.**

- **서버 템플릿을 안 읽습니다** (Hugo·Jinja·ERB). 그런 프로젝트에서는
  `--exclude` 하거나 `missing-selector`를 끄십시오.
- **런타임에 조립되는 셀렉터는 판정하지 않고 셉니다.**
- **밖에서 주입되는 클래스·변수**는 볼 수 없습니다. 끄십시오.
- **범위를 안 가립니다.** 넘긴 것 전부가 한 묶음이라, 서로 다른 앱 둘을
  같이 주면 한쪽 클래스가 다른 쪽 오타를 메울 수 있습니다. 앱마다 따로
  돌리십시오.
- **파서가 아닙니다.** 손으로 쓴 토크나이저가 주석·문자열·템플릿·정규식을
  먼저 지웁니다. 그래서 의존성이 0입니다. 낯선 문법은 그냥 판정 안 되고,
  **그 사실을 말해 줍니다.**

## 설계 규칙

전부 실제로 값을 치르고 배운 것입니다.

1. **모르는 것과 없는 것은 다르다.** 못 푼 조회는 세고, 보고하지 않는다.
2. **건너뛴 검사는 밝힌다.** 침묵이 통과로 읽히면 안 된다.
3. **짐작보다 "모른다"가 낫다.** 모호한 상수는 **만드는 자리에서는** 넉넉히
   받아들이고(거짓 경보만 줄어든다) **조회하는 자리에서는** 포기한다(짐작이
   자신 있는 오답을 만든다).
4. **진짜 실패 모드는 거짓 경보다.** 시끄러운 린터는 꺼지고, 꺼지면 진짜
   발견도 같이 사라진다. 위의 모든 막이는 **빼면 깨지는 시험**으로 덮여 있다.

`npm test` 가 95가지를 돌립니다.
